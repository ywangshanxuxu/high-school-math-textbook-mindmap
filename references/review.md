# PDF 与数学公式复核

自动步骤：pypdf 提取逐页文本；正则识别“第…章”和“1.1 / 1.1.1”标题；匹配数学符号的行进入候选队列。只有原文显式 `$...$` 时复制其 LaTeX，其余候选 latex=null。真实教材 PDF 通常不含 LaTeX，本项目不会自动恢复二维公式。

章节清理：先对照目录与正文。移除页眉/页脚生成的节点时保留 pages.text；合并断行时严格教材标题不能更改原文，可保留原文行节点并在复习模式做概括。需要改写原文的转录纠错应记录 page.note，保存原始提取 JSON 作为审计基线。sources.quote 和 line 始终对齐当前 pages.text。

逐页复核清单：

- 空白页是否为扫描页、插图页或确实空白？扫描/图页需手工描述/转录并注明 extraction=manual；真正空白页可填写“[经核对为空白页]”并记录 note，不可默默略过。
- 标题、章节顺序、定义前提、符号约定、例题和图表是否遗漏？正则识别不到的标题要人工建节点并改层级。
- 集合关系的包含符号、开闭区间、正负号、上下标、根式范围、分式分子分母、绝对值、对数底数、分段条件、向量记号是否与视觉原稿一致？
- 比较 PDF 图像与 KaTeX 渲染，并检查适用条件及含义。写下 reviewer 和核对 note 后才批准；不要用语法校验代替此步骤。

算法可能漏掉不含匹配符号的公式，也可能将普通句子列为公式。误报需人工删除候选/对应引用并在 page.note 记录；漏报需添加带来源的公式。扫描件/OCR、二维公式、几何图、表格、手写注释未实现。外部 OCR 输出必须作为不可靠转录继续复核。

KaTeX 使用 throwOnError=true、trust=false、strict=error、maxExpand=1000，阻止不支持语法进入正式输出；无法渲染的公式草稿显示错误文本。支持渲染的内容仍可能语义错误。配置不提供自动“全部批准”命令。

`validate --pdf` 对比当前 PDF 与 SHA256，只证明文件身份一致。人工更改 pages.text 无法自动核实与原始 PDF 的视觉一致性。正式门禁检查签署、页覆盖、引用、原文一致、树顺序及渲染语法，不能认证教师审核质量。
